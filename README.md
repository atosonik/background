# Face Swap & Background

Offline desktop photo editor. Two things:

- **Swap a face** — click a face in a group photo, supply someone else's photo, replace just that person.
- **Replace the background** — keep everyone in the picture, change everything behind them.

No PyTorch, no cloud, no telemetry. The whole pipeline is onnxruntime, and it
runs with the network unplugged.

## First run after cloning

The model files are **not** stored in this repo as-is — they are committed as
≤1 MB parts under `parts/`, so the first step is to reassemble them:

```
py -3.12 -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt

python chunker.py merge        # parts/ -> models/  (1.2 GB, checksummed)
python selftest.py             # 18 checks, should end "All checks passed."
run.bat                        # the app
```

**Use `run.bat`, not `python ui.py`.** The dependencies live in `.venv`; a plain
`python` fails at the first import, and if you double-clicked it the console
closes before you can read why. `run.bat` uses the right interpreter and checks
the models are present first.

Prefer not to reassemble? `python download_models.py` fetches the same models
over the network instead.

## Run

```
python selftest.py                                   # verify the install
run.bat                                              # desktop app (Help button, or F1)

python cli.py photo.jpg --list -o boxes.jpg          # numbered preview of every face
python cli.py photo.jpg new.jpg --face 2 -o out.jpg
python cli.py photo.jpg new.jpg --point 812 430 -o out.jpg
python cli.py photo.jpg new.jpg --face 1 --tone 0.8 --blend 0.9 -o out.jpg
```

The output path is the `-o` flag, not a positional argument. `--face` is
1-based, matching the numbers drawn on the `--list` preview and shown in the GUI.
The CLI covers face swap only; background replacement is GUI-only.

## Swapping a face

Click the face, load the new person's photo, press **Swap face**. Only that
person changes — verified on a five-person photo: the target face changed and
all four bystanders came back **0 pixels** different.

Measured by `selftest.py` on the bundled test images:

| Check | Result |
|---|---|
| Self-swap, cosine to the original identity | **0.811** (1.0 = identical) |
| Cross-swap, cosine to the *source* person | **0.634** (ArcFace calls >0.4 same person) |
| Cross-swap, cosine to the *original* face | **0.168** (identity genuinely replaced) |
| Skin-tone ΔE vs the original face, tone 0 → 1 | **2.18 → 0.89** |

**Skin tone match** applies a LAB mean/std transfer inside the face contour,
pulling the new face into the photo's own lighting. `inswapper_128`'s 128px
decoder drifts warm and light, which on Asian skin reads as a wrong complexion
and leaves a seam at the jaw. 70–100% is the useful range. It corrects colour
only — identity lives in high-frequency detail that first-order statistics leave
alone.

Two things matter more than any slider:

- **Match the pose.** The single biggest quality lever. A frontal source onto a
  face pitched steeply downward came out visibly smeared even though the identity
  metric still read 0.634 — the right face, rendered badly.
- **Don't swap the recogniser.** `inswapper_128` carries a baked-in `emap` matrix
  fitted to `buffalo_l`'s `w600k_r50` embedding space. Substituting `antelopev2`,
  often suggested because it scores better on Asian benchmarks, feeds it
  embeddings from a different space and degrades the output to a blurry average
  face. `buffalo_l` is not optional.

## Replacing the background

Load a photo, switch to the **Background** tab, open any image, press **Replace
background**. Measured on a real family photo: **people kept 99.9%, background
replaced 99.6%**, in 1.9 s.

**Quality dropdown.** "Fast" is `u2net_human_seg` (320px input, ~1.5 s). "Best
hair detail" is `birefnet_lite` (1024px input) — it resolves individual hair
strands where the fast model cuts hair as a solid blob, at ~17× the CPU cost.
Measured on a 3-person photo: 1.12 s vs 19.19 s.

**Edge softness** re-composites from a cached matte, so it stays live on a large
photo — dragging it runs no model at all.

Three fixes in here were found by testing and are worth knowing about if you
change this code:

- **The matte runs per person, on a crop.** One 320×320 pass over a wide group
  photo starves everyone at the edges: on a 2032×900 frame the rightmost person
  came back at 0% coverage. Cropping first gives each person full input
  resolution.
- **Letterbox, never squash.** Resizing straight to 320×320 ignoring aspect ratio
  scored 0% on the left-hand person of that same frame; letterboxing scored 93%.
- **Holes get filled.** Where the model is unsure — a light jacket, a highlight
  on a cheek — it returns near-zero alpha *inside* a person and the new
  background shows through as a bright blotch. `fill_holes` flood-fills from the
  frame border to find enclosed gaps and closes only the small ones, so a real
  gap between an arm and the body stays open. Interior blotches: 0.20% → 0.040%.

## The standalone .exe

A single-file Windows build lives in this repo as parts:

```
python chunker.py merge --parts runableparts     # -> dist/FaceSwap.exe (183 MB)
```

It needs no Python. It does need `models/` **next to the .exe**:

```
FaceSwap.exe
models/            <- from: python chunker.py merge
```

`FaceSwap.exe --selftest` runs the same 18 checks without a Python install — the
packaged build passes all of them, cold start included, in about 19 s.

To rebuild it:

```
pip install pyinstaller
python -m PyInstaller --noconfirm --clean FaceSwap.spec
```

[FaceSwap.spec](FaceSwap.spec) is not a stock spec — read the comment blocks
before changing it. In short: `onnxruntime` must not be `--collect-all`ed (its
analysis subprocess crashes on `onnx.reference`), `matplotlib` cannot be excluded
however unused it looks (`insightface.app` imports it transitively at import
time), and the bundled MSVC runtime DLLs are stripped because PyQt5 and
scikit-learn ship different builds under the same filename and the loser breaks
onnxruntime.

The exe is console-mode on purpose: a onefile GUI that dies during import has no
window to show an error in. It also extracts ~183 MB to a temp folder on each
launch, which is what onefile costs.

## Splitting big files into parts

[chunker.py](chunker.py) cuts a file or folder into parts of at most 1 MB and
puts them back byte-for-byte, for when the whole file can't be moved in one
piece — a size-limited transfer, or a git host.

```
python chunker.py split                                  # models/ -> parts/
python chunker.py split --src dist/FaceSwap.exe --parts runableparts
python chunker.py verify --parts runableparts            # checksums only, no writes
python chunker.py merge  --parts runableparts            # restores dist/FaceSwap.exe
```

Default part size is **1,000,000 bytes** — under "1 MB" whether read as 10⁶ or
2²⁰. `--size` accepts `900KB`, `1MiB`, `512K`.

The manifest records a SHA-256 for every part *and* for each whole file. `merge`
checks both and assembles into a `.merging` temp file that is only moved into
place once the full-file hash matches, so a bad part can never leave a
half-written file where something would load it. Verified against all three
failure modes:

| Damage | Result |
|---|---|
| One bit flipped, size unchanged | `part 00250.bin failed its checksum`, exit 1 |
| Part truncated | `is 900000 bytes, expected 1000000`, exit 1 |
| Part deleted | `1 part(s) missing, first 00250.bin`, exit 1 |

A size check alone would miss the first of those. Splitting a single file puts
its parts flat in the output folder; splitting a directory mirrors the tree.
`merge` skips anything already correct, so re-running it is cheap.

## Import order (do not "tidy" this)

`ui.py` imports `swapper` **above** its PyQt5 imports, and `swapper.py` imports
`onnxruntime` eagerly at module scope. This is load-bearing on Windows:

```
import onnxruntime; from PyQt5 import QtWidgets   # works
from PyQt5 import QtWidgets; import onnxruntime   # DLL initialization routine failed
```

Letting an import sorter alphabetise those lines makes the GUI crash on startup
with a bare `0xC0000409`, which points nowhere near the real cause. `swapper.py`
catches that ImportError and re-raises it with an explanation.

## Known limits

- The swapped face is rebuilt at **128×128** before paste-back. On a
  phone-resolution photo it will look softer than the rest of the frame. A
  GFPGAN/CodeFormer restoration pass is the usual fix; it is not wired in. If you
  add one, prefer CodeFormer at a high fidelity weight (~0.7–0.9) — its face
  prior otherwise pulls features toward its own training distribution.
- No CUDA provider was available where this was measured, so all timings are
  CPU. Swapping `onnxruntime` for `onnxruntime-gpu` (CUDA 12 + cuDNN 9) takes a
  swap from ~1 s to roughly 40 ms and makes the accurate matte model practical.
- Glasses, heavy occlusion and extreme profiles all degrade the face swap.
- One face at a time. Replacing a second face means saving and reopening the
  result; the app does not chain swaps.
- **Clothing replacement was attempted and removed.** Recolouring could not do
  what was wanted (a t-shirt cannot become a uniform without generating one), and
  the diffusion try-on route needs PyTorch plus several gigabytes of
  non-commercially-licensed weights. It is not in this build.
